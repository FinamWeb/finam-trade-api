# Руководство по репозиторию

## Назначение и аудитория

В этом репозитории публикуются SDK Finam Trade API (Python, Node.js, Kotlin,
а также сгенерированные привязки для JavaScript и Go) и полные примеры торговых
стратегий. Документация в первую очередь должна помочь пользователю SDK или
стратегии безопасно получить первый результат. Инструкции для контрибьюторов и
по выпуску релизов идут после пользовательского онбординга.

## Карта репозитория

- `proto/` — исходные protobuf-контракты; управляются извне.
- `sdk/python/` — пакет `finam-sdk`, импортируется как `finam_trade_api`.
- `sdk/node/` — пакет `@finam/trade-api`: рукописный TypeScript SDK.
- `js/` — пакет `@finam/grpc-tradeapi`: «сырые» JS-привязки, сгенерированные
  buf; без клиента, аутентификации и повторов. Собирается и публикуется
  отдельно от `sdk/node`.
- `go/` — Go-модуль с закоммиченными привязками; CI перегенерирует их при
  изменении `proto/`.
- `kotlin/` — Kotlin SDK (`kotlin/sdk/`) и примеры (`kotlin/examples/`) на
  Gradle.
- `examples/sdk/` — точечные автономные приложения, которые по умолчанию
  зависят от опубликованных SDK.
- `examples/strategies/` — полные приложения-стратегии, которые по умолчанию
  зависят от опубликованных SDK.
- `docs/swagger/` и `specs/asyncapi/` — REST- и WebSocket-спецификации.
  Swagger генерируется CI из `proto/`.
- `MIGRATION_GUIDE.md` — переход со старого Trade API.
- `.env.example` — единственный шаблон для игнорируемого git корневого `.env`,
  который загружает каждый рецепт `just`.
- `justfile` — общая для репозитория командная поверхность контрибьютора.
  Используйте `just run-strategy-python`, `just run-strategy-node`,
  `just run-sdk-python` и `just run-sdk-node`, чтобы запускать примеры с этими
  общими настройками.

Перед изменением пакета или примера прочитайте ближайший README. Инструкции,
специфичные для языка, держите рядом с этим языком, а общее поведение стратегии —
в README уровня стратегии.

## Безопасность

- Никогда не коммитьте, не печатайте и не придумывайте настоящий
  `TRADE_API_SECRET`.
- Никогда не запускайте пример с `--execute` и не вызывайте пример выставления
  заявки, если пользователь явно не попросил настоящую заявку и не подтвердил её
  параметры.
- Предпочитайте тесты без учётных данных. Для онбординга предпочитайте
  ограниченный режим стратегии `--check` вместо потокового dry-run: он не
  читает счета и не выставляет заявки.
- Значения в `.env.example` должны оставаться фиктивными. Настоящие `.env`
  исключены из git.
- Есть ровно один `.env.example`, в корне репозитория. Каждый рецепт `just`
  загружает корневой `.env`, поэтому настройки примеров задаются один раз. Не
  возвращайте файлы окружения на уровне отдельных примеров.

## Сгенерированный код и публичные границы

- `proto/` управляется извне и не редактируется из этого репозитория. Не
  добавляйте, не удаляйте, не переформатируйте и никак иначе не меняйте ничего
  в `proto/`, включая комментарии и примеры в документации внутри них.
  Нужное изменение контракта делается выше по течению; сообщите о нём там и
  дождитесь синхронизированных контрактов.
- Не правьте вручную сгенерированные привязки в `sdk/node/src/generated/`,
  `sdk/python/finam_trade_api/proto/`, `go/grpc/`, `js/build/` и
  `docs/swagger/api.swagger.json`. Они дословно наследуют комментарии из
  контрактов, поэтому могут законно расходиться с документацией самого
  репозитория.
- Запускайте `just generate` после повторной синхронизации `proto/`.
- Рукописный код SDK должен открывать сгенерированную функциональность через
  существующий публичный клиент и шаблон «модуль на сервис».
- Реализации примеров должны оставаться копируемыми и импортировать только
  публичный пакет для своего языка. Они читают конфигурацию из окружения
  процесса и никогда сами не загружают файл окружения — это привязало бы их к
  структуре этого репозитория. Их закоммиченные манифесты и lock-файлы должны
  разрешаться в опубликованные артефакты; команды контрибьютора могут локально
  переопределять установленные окружения без правки этих файлов.
- Версии пакетов Python и Node.js движутся вместе, и один тег GitHub Release
  публикует все SDK репозитория (PyPI, npm, Maven Central). Python использует
  нормализованную запись PEP 440, например `2.19.1rc1`; Node.js — `2.19.1-rc.1`.
- `ReportsService` (отчёты по счёту) есть только в российском контуре: он
  входит в `proto/`, в `client.reports` Python SDK и в `api.reports` Node.js SDK.
  Это намеренное отличие от репозитория `limeint/tradingapi`, не ошибка.

## Требования к документации

- Документация пишется по-русски. Идентификаторы, команды, сообщения в логах и
  код остаются как есть, на английском.
- Команды, представленные как быстрый старт, должны работать из чистого клона
  или чистого каталога потребителя.
- Используйте `uv run python ...` после `uv sync`, если инструкции явно не
  активируют `.venv`.
- Помечайте инструкции для пререлизных реестров и фиксируйте точную
  пререлизную версию.
- Начинайте с аутентификации или рыночных данных только на чтение. Примеры с
  настоящими заявками ставьте за явным предупреждением.
- Показывайте, откуда запускать команду, какие инструменты нужны, какой
  ожидается первый вывод и какой README читать следующим.
- В примерах инструментов используйте `SBER@MISX`. Trade API разрешает
  `ticker@mic` по MIC торговой площадки; для Московской биржи это `MISX`.
- Не копируйте длинные каталоги API в инструкции для агентов; ссылайтесь на
  README пакета или на источник истины.

## Проверка

Работая, запускайте самые узкие подходящие проверки, а затем `just check` для
изменений, пересекающих границы пакетов.

```sh
# Node.js SDK
npm --prefix sdk/node run check

# Точечные примеры Node.js
npm --prefix examples/sdk/node run check

# Стратегии Node.js
npm --prefix examples/strategies/sma_crossover/node run check
npm --prefix examples/strategies/macd_zero_cross/node run check
npm --prefix examples/strategies/rsi_threshold/node run check

# Python SDK (в чистом клоне сначала сгенерируйте привязки)
(cd sdk/python && uv run ./scripts/generate_proto.sh)
(cd sdk/python && uv run ruff check finam_trade_api tests)
(cd sdk/python && uv run ruff format --check finam_trade_api tests)
(cd sdk/python && uv run mypy finam_trade_api)
(cd sdk/python && uv run pytest)

# Точечные примеры Python
(cd examples/sdk/python && uv run ruff check .)
(cd examples/sdk/python && uv run ruff format --check .)
(cd examples/sdk/python && uv run mypy .)

# Стратегии Python; STRATEGY — sma_crossover, macd_zero_cross или rsi_threshold
STRATEGY=sma_crossover
(cd examples/strategies/$STRATEGY/python && uv run ruff check .)
(cd examples/strategies/$STRATEGY/python && uv run ruff format --check .)
(cd examples/strategies/$STRATEGY/python && uv run mypy .)
(cd examples/strategies/$STRATEGY/python && uv run pytest)

# Kotlin SDK и примеры
(cd kotlin && ./gradlew build)
```

Не используйте `npm run format`, `ruff --fix` или другой изменяющий форматтер
во время ревью только на чтение.
