# Примеры стратегий Finam

Запускаемые торговые стратегии на опубликованных SDK Trade API. Примеры
отдают предпочтение читаемому коду, безопасным значениям по умолчанию и явным
вызовам API, чтобы разработчики могли копировать приёмы — или сами каталоги — в
свои приложения.

## Первая проверка стратегии

Выберите любую реализацию. Обе команды ограничены и только читают: они
аутентифицируются, загружают исторические свечи, считают последний сигнал и
завершаются.

```sh
# Python 3.10+ и uv
cd examples/strategies/sma_crossover/python
uv sync --locked
TRADE_API_SECRET=... uv run python main.py --symbol SBER@MISX --check
```

```sh
# Node.js 20+
cd examples/strategies/sma_crossover/node
npm ci
TRADE_API_SECRET=... npm start -- --symbol SBER@MISX --check
```

Запускайте их из корня репозитория. Контрибьюторы, которым удобнее держать
секрет в одном месте, могут скопировать `.env.example` в `.env` в корне
репозитория и запускать любую стратегию через `just`, который загружает этот
файл:

```sh
just run-strategy-python sma_crossover --check
just run-strategy-node sma_crossover --check
```

Прежде чем открывать поток или включать исполнение, прочитайте
[описание SMA-стратегии](sma_crossover/).

## Доступные стратегии

| Стратегия | Правило | Языки |
| --- | --- | --- |
| [Пересечение SMA 9/30](sma_crossover/README.md) | Вход, когда SMA 9 пересекает SMA 30 снизу вверх; выход на обратном пересечении | [Python](sma_crossover/python/), [Node.js](sma_crossover/node/) |
| [Пересечение нуля MACD 12/26/9](macd_zero_cross/README.md) | Вход, когда линия MACD пересекает ноль снизу вверх; выход после двух подряд снижающихся значений MACD | [Python](macd_zero_cross/python/), [Node.js](macd_zero_cross/node/) |
| [Пороги RSI 14](rsi_threshold/README.md) | Вход, когда RSI опускается ниже 0.2; выход, когда RSI поднимается выше 0.8 | [Python](rsi_threshold/python/), [Node.js](rsi_threshold/node/) |

Все стратегии используют одни и те же флаги и переменные окружения, поэтому
команда проверки выше работает в любом из каталогов. Читайте их по возрастанию
сложности: правило SMA самое простое — симметричное пересечение; правило MACD
добавляет асимметричный выход и нужное для него отслеживание позиции; правило
RSI построено на двух уровнях, а не на пересечениях, поэтому зависит от
отслеживания позиции ради корректности, а не удобства. RSI — единственное
здесь правило возврата к среднему: оно покупает слабость там, где два других
следуют за силой.

## Структура и соглашения авторов

У каждой стратегии свой каталог, а каждая языковая реализация живёт внутри
него:

```text
examples/
  strategies/
    <strategy>/
      README.md          # правило, работа со свечами, защитные проверки, настройки
      python/            # самодостаточная реализация + её README
      node/              # самодостаточная реализация + её README
```

Реализации остаются плоскими внутри языкового каталога: исходные файлы на
верхнем уровне, без обёртки в пакет. В каталоге одна программа, так что лишняя
вложенность лишь повторяла бы имя стратегии.

README стратегии не зависит от языка и является единственным источником истины о
поведении. Языковые каталоги документируют только установку, запуск и тесты для
своей экосистемы.

## Соглашения

Каждая добавляемая сюда реализация должна:

- зависеть от **опубликованного** SDK для своего языка, а не от исходного
  дерева этого репозитория — тогда код примера совпадает с тем, что пишет
  пользователь пакета, а каталог остаётся запускаемым после копирования;
- быть самодостаточной: собственный манифест зависимостей и конфигурация
  инструментов, чтобы для запуска не требовался ни один файл вне каталога;
- отделять расчёт сигнала от кода API и заявок;
- оценивать закрытые свечи, а не изменяющиеся;
- стартовать в режиме dry-run и требовать явный флаг перед выставлением заявок;
- соблюдать защитные проверки, описанные в README стратегии;
- использовать переменные окружения, задокументированные стратегией, читая их из
  окружения процесса, а не из файла;
- включать точечные unit-тесты, которым не нужны ни учётные данные, ни сеть.

Эти примеры — учебный материал, а не production-система торговли. Приложениям на
их основе всё равно нужны постоянное состояние, мониторинг, лимиты риска,
сверка и операционный контроль, соответствующие их задаче.
