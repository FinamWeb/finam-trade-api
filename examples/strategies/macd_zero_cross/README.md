# Пересечение нуля MACD 12/26/9

Стратегия только в лонг на MACD, реализованная по одному разу на каждый язык
против соответствующего опубликованного SDK Trade API.

| Язык | Реализация | SDK |
| --- | --- | --- |
| Python | [`python/`](python/) | `finam-sdk` |
| Node.js | [`node/`](node/) | `@finam/trade-api` |

## Быстрый старт: проверка истории только на чтение

Запустите одну из реализаций из корня репозитория. Режим проверки
аутентифицируется, загружает исторические свечи, печатает последние
подтверждённые значения MACD и завершается. Он не читает счёт, не открывает
поток и не выставляет заявку.

```sh
# Python 3.10+ и uv
cd examples/strategies/macd_zero_cross/python
uv sync --locked
TRADE_API_SECRET=... uv run python main.py --symbol SBER@MISX --check
```

```sh
# Node.js 20+
cd examples/strategies/macd_zero_cross/node
npm ci
TRADE_API_SECRET=... npm start -- --symbol SBER@MISX --check
```

Ожидаемый вывод начинается так:

```text
History check passed: close=... macd=... macd_signal=... histogram=... signal=...
```

Эта страница описывает саму стратегию: правило, работу со свечами и защитные
проверки, которые обязана соблюдать каждая реализация. У каждого языкового
каталога свой README только про установку, запуск и тесты для этой экосистемы.

## Правило

Линия MACD — разность двух экспоненциальных скользящих средних по ценам закрытия
закрытых свечей: `EMA 12 − EMA 26`. Выше нуля быстрая средняя опережает
медленную, что читается как разворот вверх.

- **Вход:** предыдущий MACD ≤ 0, и текущий MACD > 0 — линия пересекает ноль из
  отрицательной зоны в положительную, пока стратегия вне позиции.
- **Выход:** два подряд снижающихся значения MACD — `current < previous <
  older` — пока стратегия держит позицию.
- Сигнальная линия (`EMA 9` от линии MACD) и гистограмма (`MACD − сигнальная
  линия`) считаются и логируются для контекста. Ни одно правило их не читает,
  поэтому пересечение MACD и сигнальной линии само по себе не сделка.
- Средние считаются по ценам закрытия закрытых свечей.
- Пока средние прогреваются, сигнал не выдаётся.

Вход — событие, а выход — условие, поэтому они не симметричны:

- пересечение нуля, когда позиция уже есть, не увеличивает её;
- снижающиеся значения вне позиции не являются выходом;
- самый ранний возможный выход — вторая свеча после входа, потому что свеча,
  пересекающая ноль снизу вверх, сама является растущей;
- линия MACD, вернувшаяся ниже нуля, сама по себе не выход. На практике падение
  сначала даёт два снижающихся значения, что и закрывает позицию.

### Прогрев

Первому значению MACD нужно 26 закрытий. Сигнальная линия усредняет девять
значений MACD, добавляя ещё восемь, поэтому оценке нужны **34 закрытых
закрытия** — 35 свечей, потому что самая новая ещё в ожидании. `--check`
завершается понятным сообщением, если запрошенный таймфрейм не может их дать.

В отличие от простой скользящей средней, EMA несёт всю свою историю, поэтому
значение зависит от того, где средняя началась. Реализации сеют первую EMA
простым средним и держат последние 260 закрытий (десять медленных окон) во
время потока. Этого достаточно, чтобы посев больше не влиял заметно на новейшее
значение MACD, и перезапущенный процесс сходился к тем же числам.

Каждый SDK уже предоставляет все нужные операции. Реализация не должна
импортировать сгенерированные заглушки напрямую или строить собственный

## Как обрабатываются закрытые свечи

Самая новая историческая или потоковая свеча держится в ожидании. Обновления с
той же меткой времени заменяют её. Только свеча с более поздней меткой времени
подтверждает, что ожидающая свеча закрылась, и тогда та передаётся в расчёт MACD.

Исторические свечи прогревают средние без выставления заявок.

## Как отслеживается позиция

Поскольку правило выхода — условие, а не пересечение, стратегия должна знать,
держит ли она позицию. Каждая реализация хранит один флаг в памяти:

- при каждом запуске он начинается с «вне позиции», и стратегия никогда не
  присваивает позицию, которую не открывала;
- флаг следует за тем, что подразумевает исполненный сигнал: лонг после входа,
  вне позиции после выхода;
- вход, заблокированный защитной проверкой, не присваивается, поэтому стратегия
  остаётся вне позиции и может действовать на следующем сигнале;
- выход, заблокированный потому, что на счёте ничего нет, всё равно сбрасывает
  флаг — проверка только что подтвердила, что стратегия вне позиции, поэтому
  неисполненная заявка не может её «подвесить»;
- dry-run тоже устанавливает флаг, поэтому его лог чередует вход и выход вместо
  повторения выходов на каждой снижающейся свече.

Флаг живёт в памяти. Перезапущенный процесс снова вне позиции, что бы ни было на
счёте.

## Защитные проверки

По умолчанию dry-run. Чтение рыночных данных и печать сигналов не смотрят на
счета токена и никогда не должны читать счёт или выставлять заявку. Настоящая
торговля требует явного флага согласия. На старте стратегия получает ID счёта
через `AuthService.TokenDetails` и отказывается торговать, если токену
доступно не ровно один счёт.

Перед отправкой заявки:

- вход требует, чтобы текущая позиция была ровно нулевой;
- выход требует положительной длинной позиции;
- количество на выходе ограничено текущей длинной позицией, что исключает
  открытие шорта;
- свеча сигнала даёт детерминированный клиентский ID заявки.

Используйте для этого примера выделенный счёт. API отдаёт агрегированную
позицию по инструменту, поэтому процесс не отличит позицию, открытую вручную, от
открытой стратегией. Настоящие рыночные заявки также несут ценовой риск и риск
ликвидности.

## Настройки

Каждая реализация читает одни и те же настройки из флагов или переменных
окружения. Их задаёт один общий файл в корне репозитория, и каждый рецепт `just`
загружает его автоматически:

```sh
# Из корня репозитория
cp .env.example .env
# Отредактируйте .env, затем:
just run-strategy-python macd_zero_cross --check
just run-strategy-node macd_zero_cross --check
```

Сами программы никогда не читают `.env`. Чтобы запустить одну из них напрямую из
языкового каталога, сначала экспортируйте файл:

```sh
set -a
source ../../../../.env
set +a
```

Репозиторий игнорирует `.env`; никогда не коммитьте настоящие секреты.
Переменные, уже экспортированные в оболочке, имеют приоритет над файлом.

| Переменная окружения | Обязательна | По умолчанию |
| --- | --- | --- |
| `TRADE_API_SECRET` | Да, если не передан `--secret` | — |
| `TRADE_API_SYMBOL` | Да, если не передан `--symbol` | — |
| `TRADE_API_TIMEFRAME` | Нет | `M5` |
| `TRADE_API_QUANTITY` | Нет | `1` |
| `TRADE_API_LOG_LEVEL` | Нет | `INFO` |

Инструменты записываются как `ticker@mic`, например `SBER@MISX`. Поддерживаемые
таймфреймы: `M1`, `M5`, `M15`, `M30`, `H1`, `H2`, `H4`, `H8`, `D`, `W`, `MN` и
`QR`. Окна MACD — часть правила и из командной строки не настраиваются.
`evaluate` принимает их аргументами, поэтому копия примера может работать с
другими настройками, передав их в вызове внутри `runner`:

```python
# Определено в python/strategy.py, вызывается из python/runner.py.
evaluate(closes, in_position, fast_window=12, slow_window=26, signal_window=9)
```

```ts
// Определено в node/strategy.ts, вызывается из node/runner.ts.
evaluate(closes, inPosition, /* fastWindow */ 12, /* slowWindow */ 26, /* signalWindow */ 9);
```

Оба модуля выводят прогрев из этих окон, поэтому более короткая или длинная
настройка меняет, сколько свечей нужно первому сигналу; число сообщают
`required_closes` и `requiredCloses`.

## Smoke-тест только на чтение

Каждая реализация предлагает режим проверки, который аутентифицируется,
загружает исторические свечи, считает последние подтверждённые значения MACD,
печатает одну строку и завершается, не открывая поток, не читая счёт и не
выставляя заявку:

```text
History check passed: close=... macd=... macd_signal=... histogram=... signal=...
```

Значения MACD округляются до шести знаков только для вывода; правило сравнивает
полные значения.

## Что логирует dry-run

Без `--check` стратегия читает поток и пишет по одной строке на закрытую свечу
плюс предупреждение всякий раз, когда срабатывает сигнал. В этом фрагменте
линия MACD пересекает ноль и открывает позицию:

```text
History ready: close=108.38596018061494 macd=-0.824422 macd_signal=-1.716780
Closed bar: close=109.46749318524913 macd=-0.476849 macd_signal=-1.468793 histogram=0.991944 signal=none
Closed bar: close=110.34030597120521 macd=-0.129474 macd_signal=-1.200930 histogram=1.071456 signal=none
Closed bar: close=110.91996935976759 macd=0.190403 macd_signal=-0.922663 histogram=1.113066 signal=entry
DRY RUN: entry 2 units of SBER@MISX
```

Обе реализации выводят одинаковый текст сообщений. Python пропускает его через
`logging`, поэтому каждая строка несёт ещё метку времени, уровень и имя логгера;
Node.js печатает только сообщение. `--log-level WARNING` оставляет только строки
сигналов и заявок.

В режиме исполнения строка `DRY RUN` заменяется результатом проверки —
отправленной заявкой с её ID и статусом либо причиной, по которой заявка
пропущена.

## Рамки

Это учебный материал, а не production-система торговли. Приложениям на его
основе всё равно нужны постоянное состояние, переподключение потока, добор
пропущенных свечей, мониторинг, лимиты риска, сверка и операционный контроль,
соответствующие их задаче. В частности, отслеживание позиции живёт только в
памяти, и настоящее приложение заменило бы его сверенным постоянным состоянием.
